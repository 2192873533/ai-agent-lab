## 一、手写 Agent 时踩的 10 个坑

| # | 我写的 | 错在哪 | 学到的概念 |
|---|---|---|---|
| 1 | `os.getenv("sk-cc54...")` | 参数应该填**变量名**不是值 | 配置与代码分离 |
| 2 | `messages="你好"` | 应该是"列表装字典" | 对话的数据结构 |
| 3 | 删掉了 `print(...)` | 表达式求值 ≠ 输出 | 输出是显式动作 |
| 4 | `create()` 参数间漏逗号 | 除最后一个外都要有逗号 | Python 换行语法 |
| 5 | 变量名 `tool` / `my_tools` 不一致 | 定义了 A，用了 B | 名字必须对上 |
| 6 | `propreties` / `experssion` | 键名是 API 契约，一字不能错 | 字典没有编译期检查 |
| 7 | description 写成"助我找到工作" | **description 是写给模型看的** | 提示词工程 |
| 8 | `message.append(message)` | 单数是元素，复数是容器 | 命名即提示 |
| 9 | `json.load` | 应该 `json.loads`（s = string） | load 读文件，loads 读字符串 |
| 10 | 以为点链可以凭感觉写 | 层数由数据结构决定 | 打点看补全 / print |

**这 10 个坑没有一个是"我笨"——它们都是 Python + API 编程的真实难点。**

## 二、三个"能演示 vs 能上生产"的差异

对照 `chapter1/web-search-agent/agent.py` 的源码：

### 1. assistant 消息要重建为纯 dict

```python
# ❌ 把 SDK 对象直接塞回去（DeepSeek 宽容，能跑）
messages.append(message)

# ✅ 手工重建为纯 dict（能换厂商）
messages.append({
    "role": "assistant",
    "content": message.content or "",
    "tool_calls": [...],
})
```

源码注释：直接塞 pydantic 对象会附带 `reasoning_content` / `refusal`
等额外字段，回传给 Moonshot 时触发 `tokenization failed` 400 错误。

### 2. 工具参数可能要用"原始字符串"

```python
# 这套工具协议要求传原始序列化字符串，即使已经解析过了
tool_result = self._execute_formula(name, tool_call.function.arguments or "{}")
```

工具协议不统一，要按对方的文档来。

### 3. JSON 解析失败不能崩

```python
try:
    args = json.loads(call.function.arguments or "{}")
except json.JSONDecodeError:
    args = {}          # 模型偶尔生成坏 JSON，兜住继续跑
```

不加 try/except，程序会直接挂掉。

## 三、环境相关的坑

| 症状 | 原因 | 解法 |
|---|---|---|
| `ModuleNotFoundError: No module named 'openai'` | **虚拟环境没激活**（99% 是这个） | 看提示符有没有 `(.venv)` |
| 中文/emoji 乱码 | 终端编码不是 UTF-8 | `chcp 65001`，或设 `PYTHONUTF8=1` |
| `os.getenv(...)` 返回 `None` | 参数填了值而不是名字 | 检查 `.env` 和参数 |
| 改了 `.env` 没生效 | `load_dotenv()` 只在启动时读一次 | **退出重跑** |
| 401 Incorrect API key | Key 和 `--provider` 不是同一家 | 检查两处是否配对 |
| 404 model not found | `--provider` 和 `--model` 串台 | 只写 `--provider` |

## 四、项目本身的坑

| 坑 | 说明 |
|---|---|
| `run_experiment_1_1.py` **不读** `.env` 的 `LLM_PROVIDER` | 它的 `--provider` 默认是 `kimi`，**必须显式传** |
| 用 ▶️ 按钮跑脚本 = 不带参数 | 会用到默认 provider。要传参数就用 `Ctrl+Shift+B` 或终端 |
| `main.py --mode single` 默认覆盖 `task_result_full.json` | 加 `--output my_result.json` |
| 上游 bug：`agent.py` 用 `openai.APITimeoutError` 却没 `import openai` | 任何 API 报错都被 `NameError` 盖住。已在本地补上 |
| 同一组实验跑两次结果不同 | **正常现象**，书里说"倾向而非定律"，别当 bug |

## 五、网络问题（国内环境）

### github.com 时通时不通

实测：

```
github.com:443   第1次 通(2.0s) → 第2次 不通 → 第3次 不通
```

**push 失败一次是常态，不是配置错了。**

解法：用仓库里的 `commit.ps1`，它自动重试 6 次。

```powershell
.\commit.ps1 "实验 1-2：完成离线 ReAct 轨迹分析"
```

### pip 装依赖很慢

用国内镜像：

```powershell
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 六、读报错的正确姿势

> **报错信息是第一手资料，问别人是第二手。**

1. **先看最后一行** —— 这里才是真正的错误原因
2. **往上找自己的文件名** —— `File ".../my_agent.py", line 47` 才是问题所在
3. **中间几十行全部跳过** —— 那是调用栈（backtrace），C 里见过

**最后一行告诉你"哪里错了"，你的文件那一行告诉你"错在第几行"。中间的全是噪音。**
