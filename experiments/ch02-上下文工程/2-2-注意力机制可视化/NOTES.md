## 一、这个实验在做什么

把模型内部的**注意力权重**画成热力图，用眼睛看它在"看哪里"。

用的是 Qwen3-0.6B，本地跑，`output_attentions=True` 抓真实的注意力张量。

---

## 二、怎么读一张热力图

**行和列都是上下文的 token。**

| 轴 | 含义 |
|---|---|
| **行** | 谁在看（Query 的位置） |
| **列** | 被看的（Key 的位置） |
| **格子里的颜色深浅** | 这个位置分到了多少注意力 |

**一行里的所有值加起来等于 1**（softmax 的结果）。

---

## 三、两个必认的形状

### 1. 因果三角（Causal Triangle）

因为用的是**因果注意力**（模型不能让 token 看到未来），所以每个 token 只能看自己和它**之前**的 token。

结果就是热力图的**右上角永远是一片空白** —— 形成一个下三角的形状。

```
       被看的 token（Key）→
     ┌───────────────────────┐
谁在看 │ ██                    │
（Q）  │ ████                  │
  ↓    │ ██████      空白      │
       │ ████████              │
       │ ██████████            │
       └───────────────────────┘
             ↑ 对角线以下才有颜色
```

**这张图直接回答了一个问题**：为什么"追加到末尾"不破坏缓存？

因为因果注意力决定了——每个 token 的隐状态（以及由它算出的 K、V）**只依赖它自己和它之前的 token**。在末尾追加新内容，不会改变任何已缓存 token 的 K、V。

### 2. 注意力汇（Attention Sink）

模型会把**大量注意力**集中到序列的第一个 token（通常是 BOS）上，哪怕它在语义上根本不重要。

**书里的实测：某些层里对首 token 的注意力能到 73.2%。**

这不是 bug，是 Transformer 的普遍现象——它像一块"注意力垃圾桶"，模型不知道看哪时就把权重倒在那里。

**这一条有个实用含义**：如果你在上下文最前面放了一段特别重要的东西，它的注意力可能会被这个"垃圾桶"稀释。

---

## 四、还能看出的三块区域

在带思维链的模型上，热力图能看出功能分区：

| 区域 | 表现 |
|---|---|
| 思考区（`<think>` 内） | 内部互相看得多 |
| 输出区（正式回答） | 大量回看思考区 |
| 推理关联 | 能看出哪一步推理依赖哪一步之前的结论 |

---

## 五、结论

1. **注意力是可观察的** —— 不用猜模型在想什么，可以把张量抓出来画图
2. **因果三角解释了 KV Cache 规则的物理来源** —— 不是工程约定，是数学性质
3. **注意力汇说明"放在前面"不等于"更受重视"** —— 位置靠前反而可能被垃圾桶吸走
4. **热力图是后面 2-8 的工具** —— 那个实验靠它来证明"状态栏真的把注意力吸过去了"
