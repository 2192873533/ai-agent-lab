# 实验 2-7 ★★ 从个人范文创建“去 AI 味”写作 Skill

> 来源：《深入理解 AI Agent》第 2 章「动态提示词与 Agent Skills」
> 正文位置：`book/chapter2.md:843`
> 官方状态：**设计**（书里没有配套代码项目，是留给读者自己做的轻量实验）

---

## 一、这个实验在干什么

实验 2-6 是**用**别人的 Skill（Anthropic 官方 PPTX Skill）。
实验 2-7 是**自己写**一个 Skill。

自己写的是最贴近日常写作的一种：**风格 Skill**。
目标是把“我平时到底怎么写文章”这件说不清的事，变成一份模型能读懂、能执行的 `SKILL.md`。

核心不是“让 AI 帮我写”，而是：

> 把个人经验外化成按需加载的指令，并观察它能不能在新文章里复现我的表达习惯。

---

## 二、书里给的做法

1. 准备 **3-5 篇自己最满意的原创文章**。
2. 让支持 Agent Skills 的运行时（这里用 Codex 本身）归纳**用词、句式、段落结构、语气**，
   生成一份 **20 行左右**的初版 `SKILL.md`。
3. 用一个**新题目**起草一篇文章，由我**逐句改稿**。
4. 比较 before / after：哪些词被删掉、哪些长句被拆开、哪些地方需要补事实。
5. 把**反复出现**的改动整理回 Skill，每条规则保留**正例 / 反例 / 适用范围**。

第 4 步是关键：**原文与修改稿的差异，比抽象地说“再自然一点”有信息量得多。**

---

## 三、验收标准（书里明说）

只要求这份 Skill 具备：

- [x] 清晰的**触发条件**（什么时候该用我 / 什么时候不该用我）→ `description` + 「作用域」一节
- [x] **三到五条**带示例的原则 → 四条，每条配正反例
- [x] 明确的**作用域**（管哪些文体 / 场景，不管哪些）→ 「作用域」一节，写明不管公告/合同/摘要
- [x] **例外**（什么情况下这条规则不适用）→ 禁止清单里每一行都有「合法例外」列

并且：**不把一次主观判断当作普遍规则。**

---

## 四、Skill 的推荐结构（宝玉《图解 Skill》，书里引用）

| 部分 | 写什么 |
|---|---|
| 角色与读者 | 这份 Skill 服务谁、面向什么任务、输出要达到什么标准 |
| 核心原则 | 只留 3-5 条最重要的判断，每条配正例 + 反例 |
| 禁止清单 | 高频错误、越权动作、容易误解的表达，并写清合法例外 |
| 参考资料 | 术语表、模板、范文、更详细的子文档 |

规则统一写法：**作用域 + 动作 + 例外 + 验证方式**。
不要堆成一张越来越长的禁用词表。

## 五、语料调查（2026-10-11）

最初想用 `D:\桌面1\` 下的三本 PDF，实测后放弃：

|---|---:|---|---|

| `经营未来：李明博自传.pdf` | 255 | 0 页 | 纯扫描图，读不了；且是韩文自传的中译本，中文字面是译者的语言 |
| `龙华集 (张春桥).pdf` | 190 | 0 页 | 纯扫描图，读不了 |

改用自己桌面上的三个 docx：

| 文件 | 内容 | 能用吗 |
|---|---|---|
| `刘嘉峰.docx` | 370 字，是"实验室约定"守则（不是原创文章） | ❌ |
| `刘嘉峰  物理论文.docx` | 1493 字，《大学物理课程对思想和生活的影响》 | ⚠️ 能用，但**满篇 AI 味** |
| `计233-1 刘嘉峰.docx` | 0 字，6 张图片 | ❌ 纯图无文字 |

### 因此调整了方法

书里的设计是：**拿自己最满意的文章**当正面范文 → 归纳"我是什么样的"。

实际情况是我手上没有正面范文，只有一篇**反面的**（AI 味浓度极高）。所以第一步反过来做：

> 从负面标本里提炼**"我不要什么样的"** → 先做成 `禁止清单` → 再按书里的正常流程，
> 用一个新题目起草、本人亲手改稿，把"我要什么样的"补进去。

这不是偷懒，教学上反而更清楚：**删什么比加什么容易观察得多**，而且实验目标本来就叫"去 AI 味"。

### 标本的风格指纹

| 指标 | 这篇论文 | 对照：自然中文（家书类） |
|---|---|---|
| 平均句长 | **39.3 字** | 22.9 字 |
| `不仅……更……` | 8 次 | 4 次 / 10 万字 |
| `积极的影响` | 5 次 | 0 |
| `深远的影响` | 4 次 | 0 |
| `科学素养` | 7 次 | 0 |
| `因此/其次/此外/最后/总之` | 6 次 | 极少 |
| 感叹号 / 问号 / 分号 | 0 / 0 / 0 | 0.9 / 4.0 / 0.4 每千字 |

## 八、和前面学过的对上号

| 前面学过的 | 在这个实验里对应什么 |
|---|---|
| `description` 是**路由条件**，不是功能介绍 | 决定这份 Skill 什么时候被触发 |
| 渐进式披露三层 | 薄目录元数据 → SKILL.md 正文 → 范文 / 模板子文档 |
| Skill 是给**模型**看的说明书 | 规则要写成模型能执行的命令，不是给人看的感想 |
| 工具返回值决定模型能看见什么 | 改稿 diff 就是喂给模型的“反馈信号” |
| 一次主观判断 ≠ 普遍规则 | 只有**反复出现**的改动才写进 Skill |
